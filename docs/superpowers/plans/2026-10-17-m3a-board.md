# M3a: Board (browse and act) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A board window (`Ctrl+Alt+B` or the tray) that shows every captured note as a card. You can switch tabs, search, open a note to edit it in an overlay, mark it done, trash, restore, recolour it, set its due date or clone it, and undo any of those, by keyboard or mouse.

**Architecture:**
- New `app/src/board/`: `BoardModel` (a list model over `Store::list`), `CardDelegate` (paints fixed-size cards), `BoardWindow` (tabs, search, `QListView` grid, status line, actions), `NoteOverlay` (`NoteEdit` + `CaptureController` on top of the board) and `UndoLog`.
- `CaptureController` gains `open(id)` and a `saved` signal, so the overlay reuses capture's autosave, done and colour logic.
- `App` creates the board on demand, registers the board hotkey and reloads the board when a capture saves.

**Tech Stack:** C++20, Qt 6.10.3 Widgets (`QListView` icon mode, `QStyledItemDelegate`), `noite-core`, Win32 (`GetProcessMemoryInfo` for the gate), CMake + Ninja + MSVC, Qt Test offscreen.

**Spec:** [`docs/superpowers/specs/2026-10-17-m3a-board-design.md`](../specs/2026-10-17-m3a-board-design.md) (decisions B1–B7) and [`docs/spec.md`](../../spec.md) §6, §4, D5, D9, D11, D20, D30.

## Global Constraints

- Qt Widgets only: no QML or Qt Quick (B1), and no Qt Network (D13).
- Widgets never touch files: everything goes through `noite::Store` or `AttachmentStore` (D14).
- Tabs: Today · All · Completed · Trash. The order comes from `Store::list`, and the UI never re-sorts.
- Search debounce: **120 ms**. Autosave stays **400 ms** (`CaptureController::kAutosaveMs`).
- Grid keys: arrows move, `Enter` opens, `N` new, `D` done/reopen, `Del` trash/restore, `Ctrl+Z` undo, `Ctrl+Shift+C` colour, `/` search. `Esc` clears a non-empty search, otherwise closes the board.
- Overlay keys: `Esc` or a backdrop click saves and closes, `Ctrl+Enter` marks done and closes, `Ctrl+Shift+C` colour, `@tokens` set the due date.
- Colour cycle: none → red → orange → yellow → green → blue → purple → none (one implementation, shared with capture).
- Board hotkey: `Settings::boardHotkey` (default `Ctrl+Alt+B`). If it's taken, the tray warns and the app keeps running.
- Tray: left-click opens the **board**; the menu has New note · Board · Quit (B5).
- The board is created on first open and destroyed on close (B6). Tab and search survive a close/reopen for the app session (B4).
- Performance: board open with 2,000 notes **≤ 300 ms p95** (cold, Release); private memory after closing **≤ 80 MB** (D5).
- Note HTML and cards store no absolute colours. Card tints come from a fixed light/dark table chosen by `QStyleHints::colorScheme()` (D30).
- App tests must never register the user's real hotkeys: `prepare()` in `tst_app.cpp` sets **both** `captureHotkey` and `boardHotkey` to rare combos.
- Edit files only with the Edit/Write tools; never round-trip them through Windows PowerShell `Get-Content`.

## Review Focus

1. **A stale card:** the note changed state elsewhere (e.g. trashed by an earlier action, or the store disagrees). An action on it shows the error in the status line and reloads, with no crash and no ghost card. Test in Task 6 (`staleCardActionReloads`).
2. **An empty tab or no search results:** the grid shows "No notes" or "Nothing matches", and `D`/`Del`/`Enter`/`Ctrl+Shift+C` do nothing. Tests in Task 3 (`emptyStateMessage`) and Task 6 (`actionsOnEmptyGridAreNoOps`).
3. **Search text with FTS syntax** (`"`, `*`, `-x`, `AND`, `(`, `NEAR`): no exception, results or none. Test in Task 1 (`searchWithQueryOperatorsDoesNotThrow`).
4. **Closing the board while the overlay has unsaved text** (`Alt+F4`, tray Quit, inside the 400 ms debounce): the text is saved. Test in Task 7 (`closingBoardWithOverlayOpenSaves`).
5. **Unbreakable or wide text on a card:** a 300-char word with no spaces, emoji, RTL text. It's elided inside the card with no overflow or crash. Test in Task 2 (`paintsHostileText`).
