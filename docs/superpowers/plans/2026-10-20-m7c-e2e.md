# M7c End-to-End Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real-keystroke end-to-end run (capture → board → done → trash → restore), checked against `noite.db`, on every CI push.

**Architecture:** The board gains `Ctrl+1`…`Ctrl+4` tab shortcuts. `tools/e2e/` holds a harness target window (leak catcher), a Python database checker, and `run-e2e.ps1`, which drives noite with `SendKeys` and checks each step with the checker. CI runs it after the benches.

**Tech Stack:** C++20, Qt 6.10.3 Widgets, Qt Test; PowerShell 5.1 + WinForms `SendKeys`; Python 3 `sqlite3` (stdlib only); GitHub Actions `windows-latest`.

**Spec:** `docs/superpowers/specs/2026-10-20-m7c-e2e-design.md`

## Global Constraints

- Real keystrokes run on a PC **only after the author says they are away**; ask before the local run (Task 3).
- No test hooks in the app; checks read `noite.db` read-only (`file:<db>?mode=ro`, URI mode).
- No fixed sleep decides pass/fail; waits poll a condition with a timeout (window/file 10 s, database 5 s). Short pauses (≤ 400 ms) only pace keystrokes.
- Note text `e2e buy milk`; hotkeys `^%j` (capture), `^%b` (board); harness window title `noite-e2e-target`.
- Python runs as `python -I`, stdlib only.
- `.github/workflows/ci.yml` stays ASCII-only; scripts under `tools/` stay ASCII-only too (PowerShell 5.1 reads BOM-less files as ANSI).
- `spikes/` is not modified.
- Edit sources with the Edit tool, not PowerShell text round-trips.
- Build `tools\build.ps1 -Config Release`; tests `tools\run-tests.ps1 -Config Release`.

## Review Focus

1. **The board opens on a tab other than Today** (view state restored from the last session): step 2's `d` must still act on the new note. → Task 3: the run uses a fresh data folder, and step 2 sends `^1` before `d`.
2. **Autosave hasn't flushed when `Esc` is pressed fast**: `Esc` flushes (`dismiss()`), but the checker must wait, not read once. → Task 2, `expectWaitsForALateWrite`.
3. **A note with leading/trailing whitespace or a second note with the same text**: `expect` requires exactly one matching row. → Task 2, `expectRejectsTwoMatches`.
4. **A step fails mid-run**: the harness window and noite must still be closed, or the next CI step and a local desktop are left with stray windows. → Task 3, teardown in `finally`, checked by running with a deliberately wrong `-Exe` (setup failure path) and confirming no `noite-e2e-target` window remains.
5. **`Ctrl+digit` while typing in the board's search box**: it switches tabs and keeps the search (the model keeps the search across tabs). → Task 1, `ctrlDigitSwitchesTabFromSearch`.

### Task 2: `tools/e2e/noite_db.py`

**Files:**
- Create: `tools/e2e/noite_db.py`
- Modify: `tools/run-tests.ps1` (run `python -I tools/e2e/noite_db.py --self-test` after the release tools' self-tests; a missing `python` counts as 1 failure with `MISSING python for the e2e checker self-test`)

**Interfaces:**
- Produces (CLI):
  - `noite_db.py prepare <db>` → exit 0, prints `prepared`; sets `setupCompleted: true` in `settings`(`key='settings'`) JSON, other fields kept; inserts the row if absent.
  - `noite_db.py expect <db> --text TEXT --status {active,done,trashed} [--trashed-from {active,done}] [--timeout SECONDS=5]` → exit 0 `ok: <status>` when exactly one `scratches` row has `trim(plain_text) == TEXT` and the status (and `trashed_from`); else, after the timeout, exit 1 `expected <…>, found: [<plain_text>|<status>|<trashed_from>, …]`. Polls every 100 ms with a fresh read-only connection.
  - Errors (no file, bad args): exit 2, message on stderr.
  - `noite_db.py --self-test` → exit 0 `noite_db self-test: ok`, else exit 1 naming the failed case.

- [ ] **Step 1: Write the self-test first** (inside the script, a temp folder, tables created with the real columns used: `settings(key TEXT PRIMARY KEY, value TEXT)`, `scratches(id, plain_text, status, trashed_from)`):

```
prepareSetsSetupCompleted     # {"captureHotkey":"Ctrl+Alt+J"} -> {"captureHotkey":"Ctrl+Alt+J","setupCompleted":true}
expectPasses                  # row ("e2e buy milk", "done", None) -> expect --status done: exit 0
expectWaitsForALateWrite      # a thread inserts the row after 0.5 s -> expect --timeout 3: exit 0
expectTimesOutWithWhatItFound # expect --status trashed --timeout 0.3 -> exit 1, message contains "e2e buy milk|done"
expectChecksTrashedFrom       # ("…","trashed","active") vs --trashed-from done -> exit 1
expectRejectsTwoMatches       # two rows "e2e buy milk"/"active" -> exit 1
```

- [ ] **Step 2: Run** `python -I tools/e2e/noite_db.py --self-test` with the commands stubbed (`prepare`/`expect` raising `NotImplementedError`) — Expected: exit 1, first case named.
- [ ] **Step 3: Implement** `prepare` and `expect`. **Step 4: Run the self-test** — Expected: `noite_db self-test: ok`, exit 0.
- [ ] **Step 5: Wire into `run-tests.ps1`**; run it — Expected: a `suite noite_db --self-test: exit 0` line and `TOTAL failures: 0`.
- [ ] **Step 6: Commit** — `test(e2e): database checker for the end-to-end run, with a self-test`
