# M0b: Qt 6 Widgets Spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure whether a native Qt 6 Widgets + C++ capture window meets the D5 latency budget, and find out whether `QTextEdit` can deliver the D7/D21 editor (markdown typing shortcuts, rich paste, images, tables, links, selection fragments), so the user can choose between Tauri and Qt with numbers from both.

**Architecture:** A throwaway single-process Qt Widgets app in `spikes/qt-capture/`. `RegisterHotKey` plus a `QAbstractNativeEventFilter` catch `WM_HOTKEY`. A frameless, always-on-top capture window holding a `NoteEdit` (a `QTextEdit` subclass) is created at startup and kept hidden. The editor features live in two small units, `MarkdownShortcuts` and `NoteEdit::insertFromMimeData`, and are covered by Qt Test. The PowerShell harness from M0 is parameterised and reused, so both stacks are measured the same way.

**Tech Stack:** Qt 6 (latest 6.x on the `win64_msvc2022_64` arch, installed via `aqtinstall`; the exact version is recorded in Task 1), C++20, CMake + Ninja (bundled with VS Build Tools 2026), MSVC, Qt Test, PowerShell 5.1.

**Spec:** [`docs/spec.md`](../../spec.md): §2 performance budget (D5), §5 capture window and paste (D6, D7, D21). The baseline to compare against is the [Tauri spike findings](../../spikes/2026-10-hotkey-latency.md).

## Global Constraints

- Windows 11 x64; single process; no WebView, no QML (this decision was settled in conversation: Widgets for the spike, the board's toolkit is decided in M3).
- Hotkey `Ctrl+Alt+J` (`Ctrl+Alt+N` is taken on this PC). Register with `MOD_CONTROL | MOD_ALT | MOD_NOREPEAT`.
- The capture window is created at startup and kept hidden; the hotkey only positions, shows and focuses it (D5).
- Latency budget: hotkey → editor focused and painted **≤ 100 ms** (D5). Report memory against the Tauri baseline (176 MB private) and against D5's 80 MB.
- Trial CSV format is identical to the Tauri spike: `trial,ready_ms,text`, with `text` CSV-quoted, so `run-trials.ps1` works unchanged.
- **Automated keystroke runs happen only when the user has said they're away from the PC.** Never log other windows' titles.
- Spike code lives only under `spikes/`; results go in `spikes/qt-capture/results/` (gitignored by the existing `spikes/**/results/` rule).

## Review Focus

1. **Foreground lock:** `activateWindow()` can fall back to flashing the taskbar instead of taking focus. The failed/leaked trial counts in Task 5 catch it.
2. **First show after a long idle:** the raster backing store may be released while hidden. The idle scenario in Task 5 measures it.
3. **Hotkey already taken at startup:** must exit cleanly with a clear message, never hang. Test in Task 2 (a second instance).
4. **Huge paste** (a whole web page): the editor must stay responsive. Timed test in Task 4.
5. **Round-trip loss:** stored HTML must reload with bold, links, lists, checkboxes, tables and images intact, and `toMarkdown()` losses must be listed. Test in Task 4.

### Task 2: Hidden capture window + global hotkey

**Files:**
- Create: `spikes/qt-capture/CMakeLists.txt`, `src/main.cpp`, `src/HotkeyFilter.h/.cpp`, `src/CaptureWindow.h/.cpp`, `src/NoteEdit.h/.cpp`, `src/Trials.h/.cpp`

**Interfaces (spike-internal):**
- `class HotkeyFilter : public QObject, public QAbstractNativeEventFilter`. Methods: `bool registerHotkey(UINT mods, UINT vk)`, which wraps `RegisterHotKey(nullptr, 1, mods | MOD_NOREPEAT, vk)`; and `bool nativeEventFilter(const QByteArray&, void* msg, qintptr*) override`, which on `WM_HOTKEY` emits `pressed()`. Signal: `void pressed();`
- `class NoteEdit : public QTextEdit`. Its Task 4 overrides are declared now.
- `class CaptureWindow : public QWidget`, frameless with `Qt::Tool | Qt::WindowStaysOnTopHint | Qt::FramelessWindowHint`, 520×420. It has `void summon()` and the signal `void dismissed(QString text)`.
- `class Trials`. `void pressed()` starts a `QElapsedTimer` and bumps the trial counter. `void ready()` records the elapsed ms once per trial. `void dismissed(const QString&)` appends the row to `results/trials.csv`; the path comes from a compile-time definition pointing at the spike dir.

- [ ] **Step 1: Write the CMake project.**
  - `find_package(Qt6 REQUIRED COMPONENTS Widgets Test)`, `qt_standard_project_setup()`, `enable_testing()`.
  - A static library `capture_core` holding everything except `main.cpp`, so the app and the tests share the same code.
  - The `qt-capture` WIN32 executable linking `capture_core`.
  - A `qt-capture-tests` executable (filled in Task 4) linking `capture_core` and `Qt6::Test`, registered with `add_test`.
  - Add the definition `SPIKE_DIR="${CMAKE_CURRENT_SOURCE_DIR}"` to `capture_core`.

- [ ] **Step 2: Implement startup.**
  - `QApplication` with `setQuitOnLastWindowClosed(false)`.
  - Create the `CaptureWindow` and force native window creation (`winId()`) while it stays hidden.
  - Install the `HotkeyFilter` and register `MOD_CONTROL | MOD_ALT`, `'J'`.
  - **If registration fails:** show a `QMessageBox::critical` reading "Ctrl+Alt+J is already used by another app" and return exit code 2.
  - Log `cold_start_ms` (from `main()` entry to hotkey registered) to `results/startup.csv`.

- [ ] **Step 3: Implement `summon()`.** Get `MonitorFromWindow(GetForegroundWindow(), MONITOR_DEFAULTTONEAREST)` and pick the `QScreen` whose geometry contains that monitor's centre. Centre the window on that screen. Then `show()`, `raise()`, `activateWindow()`, `SetForegroundWindow((HWND)winId())`, and `editor->setFocus()`. If the window is already visible, refocus it only.

- [ ] **Step 4: Measure ready.** In `NoteEdit::paintEvent`, after calling the base class, report `Trials::ready()` if a trial is pending and `hasFocus()` is true. Qt's raster flush to screen follows immediately after the paint. `Esc` (`keyPressEvent`) emits `dismissed(toPlainText())`; the window clears the editor and hides.

### Task 4: Editor capability tests

**Files:**
- Create: `spikes/qt-capture/src/MarkdownShortcuts.h/.cpp`
- Modify: `src/NoteEdit.h/.cpp`
- Test: `spikes/qt-capture/tests/tst_editor.cpp`

**Interfaces:**
- `class MarkdownShortcuts : public QObject` with `explicit MarkdownShortcuts(QTextEdit* edit)`. It connects to the document's `contentsChange` and applies the rules after the triggering character:

| Typed | Result |
|---|---|
| `# ` / `## ` / `### ` at block start | heading levels 1–3 (block `headingLevel` + char size), marker removed |
| `- ` or `* ` at block start | bullet list item |
| `1. ` at block start | numbered list item |
| `- [ ] ` / `- [x] ` at block start | list item with `QTextBlockFormat::MarkerType::Unchecked` / `Checked` |
| `**text**` (on the closing `**`) | bold `text`, markers removed |
| `*text*` / `_text_` | italic |
| `` `text` `` | fixed-pitch font |
| `[label](url)` (on the closing `)`) | anchor `label` → `url` |

- `NoteEdit` overrides:
  - `insertFromMimeData`: `hasImage()` → add as a `QTextDocument::ImageResource` named `noite-att://<sha256>.png` and insert an image; `hasHtml()` → `insertHtml`; else plain text.
  - `mousePressEvent`: a click on a checkbox marker toggles Checked/Unchecked; Ctrl+click on an anchor opens it with `QDesktopServices::openUrl`.
- `NoteEdit::takeSelectionAsDocument() -> std::unique_ptr<QTextDocument>`: moves the selected `QTextDocumentFragment` into a new document and removes it from the source. This is the basis for split (requirement 22).

- [ ] **Step 1: Write the failing tests** (QTest, driving a real `NoteEdit` with `QTest::keyClicks`):

```cpp
void headingShortcut();        // keyClicks("# Title") → block headingLevel 1, text "Title"
void bulletAndNumbered();      // "- a" → list style ListDisc; "1. b" → ListDecimal
void checkboxShortcut();       // "- [ ] task" → marker Unchecked, text "task"; simulated click on marker → Checked
void boldItalicCode();         // "**b** *i* `c`" → fragment formats: bold, italic, fixed-pitch; no literal * or ` left
void linkShortcut();           // "[site](https://example.com)" → anchorAt(pos) == "https://example.com", text "site"
void pasteBrowserHtml();       // QMimeData html "<p><b>bold</b> <a href='https://x.y'>l</a></p><ul><li>i</li></ul><table><tr><td>c</td></tr></table>"
                               // → bold fragment present, anchor present, a list present, a QTextTable present
void pasteImage();             // QMimeData image 32×32 → one image format whose name starts "noite-att://" and resource loads
void insertTable();            // textCursor().insertTable(2, 2) then type into cells → table rows/cols 2×2, cell text correct
void splitSelection();         // "keep\nmove me" + image in the 2nd line; select line 2 → takeSelectionAsDocument():
                               // new doc plain text "move me" + 1 image; source plain text "keep"
void htmlRoundTrip();          // build doc with heading, bold, link, checkbox, table, image → toHtml → setHtml into new doc
                               // → all six survive (assert each); also log what toMarkdown() drops (QWARN, not a failure)
void hugePasteStaysFast();     // html with 5000 <p> lines → insertFromMimeData under QElapsedTimer; log ms; QVERIFY(ms < 500)
```

Expected: a compile failure (no `MarkdownShortcuts`, no `takeSelectionAsDocument`) or all new tests FAIL.
