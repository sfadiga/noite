# M3b: Bundles, Filter Chips and Tags — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the board: bundles as stacks that expand in place (with drag and drop), filter chips for colours, dates and tags, and a manual tag field in both editors.

**Architecture:**
- noite-core gains a `BoardFilter` applied in SQL to `list` and `tabCounts`, plus `chipFacets` and `listTags`.
- `BoardModel` rows become cards or stacks. `BoardWindow` handles expand/collapse, drops (with undo) and a `ChipBar`.
- A shared `NoteFooterBar` (tag field, inline tags, due/colour text) replaces the footer label in `CaptureWindow` and `NoteOverlay`; `CaptureController` saves the manual tags.

**Tech Stack:** C++20, Qt 6.10 Widgets/Test, SQLite (vendored), CMake + Ninja + MSVC, Windows 11.

**Spec:** `docs/superpowers/specs/2026-10-17-m3b-board-design.md` (decisions C1–C7; project spec D10, D12, D17, D18)

## Global Constraints

- Filter semantics: OR within a kind, AND across kinds. Date chips: Overdue = `due_date < today`, DueToday = `due_date = today`, NoDate = `due_date IS NULL`.
- Facet rule (C6): a chip shows if the tab, plus the search, plus the *other* kinds' active chips has at least one note matching it. Active chips always show (count may be 0).
- Tab counts follow search **and** chips (C5).
- A stack takes the position of its first member in store order and holds only matching members. A stack with no matching members produces no row.
- `D`, `Del` and `Ctrl+Shift+C` on a stack do nothing and set the status text `Open the bundle to act on its notes` (C7).
- Status texts: `Bundled into %1`, `Moved to %1`, `Removed from %1` (%1 = bundle name).
- `Esc`:
  - in the search box: clear a non-empty search, otherwise as on the grid;
  - on the grid: a member of an expanded bundle collapses it and selects the stack; else active chips clear; else the board closes.
- Tag field errors: `Invalid tag: %1`. `Ctrl+T` focuses the tag field.
- `ViewState` is session-only and gains `filter` and `expanded`.
- Performance gate unchanged: `board-bench` p95 ≤ 300 ms at 2,000 notes.
- Test command: `powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1 -Config Debug -Test` → `TOTAL failures: N`.
- Edit files only with the Edit/Write tools (no PowerShell `Get-Content` round-trips).

## Review Focus

1. A bundle with members in several tabs (one done, one active) → the stack in Today shows only the active member, and "1 note". Test: Task 2 `stackShowsOnlyMembersInTab`.
2. A card dropped onto itself, or onto the stack it already belongs to → nothing changes, no error, no undo entry. Test: Task 4 `dropOnSelfOrOwnStackIsNoOp`.
3. Tag input like `#Trip, work  #Trip`, or an invalid one like `#1abc` → saved as `trip work`; the invalid one shows `Invalid tag: 1abc` and saves nothing. Test: Task 6 `tagFieldNormalizesAndRejects`.
4. An active tag chip whose tag no longer exists on any note → the chip stays (count 0) until cleared, and the board shows "Nothing matches". Test: Task 5 `activeChipWithNoMatchesStays`.
5. Removing the last-but-one member, so the bundle ends with one note, then removing that one → the bundle disappears, the card is selected, and undo restores the bundle membership. Test: Task 4 `removingLastMembersDeletesBundleAndUndoRestores`.

- Build one `WHERE` fragment per kind from the filter. Colours: `color IN (...)`. Dates: the three predicates above, OR-ed. Tags: `id IN (SELECT scratch_id FROM scratch_tags WHERE tag IN (...))`.
