# M7c: end-to-end harness — design

**Date:** 2026-10-20 · **Status:** agreed in a brainstorming session · **Spec:** D28 (testing), `spec.md` §9 (End-to-end row: capture → board → done → trash → restore); roadmap row M7c

## Goal

- One end-to-end run that drives a real noite with **real keystrokes**: capture a note with the global hotkey, open the board with its hotkey, mark the note done, trash it, restore it.
- It checks every step against noite's database and fails on the first wrong state, on a timeout, or on a keystroke that reached the wrong window.
- It runs in CI on every push; locally only once the author says they are away.

## Decisions

| # | Decision | Why |
|---|---|---|
| E1 | Each step is checked by **reading `noite.db` read-only** from a Python script (SQLite WAL allows a reader while noite writes). No test hooks in the app. | The user's choice. The same check works on CI and locally. |
| E2 | Runs in the CI `build` job on every push, after the benches; locally via `tools\e2e\run-e2e.ps1`, **only after the author says they are away**. | The user's choice. Catches regressions at once; the no-unattended-input rule for local runs. |
| E3 | The board gets **`Ctrl+1`…`Ctrl+4`** to switch to Today / All / Completed / Trash (the `noite::Tab` order); the run restores from the Trash tab with `Del`, as a user would. | The user's choice. A real shortcut users get too; the run exercises the Trash tab. |
| E4 | The harness lives in `tools/e2e/`; `spikes/` stays untouched (throwaway history). | Kept tools are tools. |
| E5 | Every wait polls a condition (a file, a window, a database state) with a timeout; no fixed sleep decides pass or fail. Short fixed pauses only pace keystrokes. | Stable on a shared runner. |
| E6 | Keystrokes are sent with `System.Windows.Forms.SendKeys` from a dedicated harness window that catches anything that misses noite; any caught character fails the run. | The spike's proven method and leak check. |

## Part A — tab shortcuts (app)

- `BoardWindow`: `Ctrl+1` Today, `Ctrl+2` All, `Ctrl+3` Completed, `Ctrl+4` Trash, from anywhere in the board window except while the note overlay is open (the overlay's editor keeps its own keys). Implemented as window-scoped `QShortcut`s calling the existing `setTab(noite::Tab)`; the tab strip follows.
- After the switch the first card is selected; the focus stays where it was, so from the grid `D` / `Del` act on that card, and from the search box typing goes on (final-review ruling: a user mid-search keeps typing).
- Docs: `spec.md` board keys line (D30) and the README's board keys.

## Part B — `tools/e2e/`

### `harness-target.ps1`

Copied from `spikes/hotkey-latency/harness-target.ps1` unchanged in behaviour: a WinForms window titled `noite-e2e-target` with one text box; everything typed into it is written to `-Out`; it writes `<Out>.ready` once shown and closes when `<Out>.stop` appears.

### `noite_db.py` (run with `python -I`)

- `prepare <db>`: sets `setupCompleted` to true in the `settings` row (key `settings`, JSON value), keeping every other field.
- `expect <db> --text TEXT --status STATUS [--trashed-from FROM] [--timeout SECONDS=5]`: polls every 100 ms, read-only (`file:<db>?mode=ro`, URI), until exactly one row of `scratches` has `plain_text` equal to `TEXT` (trimmed) with that `status` (and `trashed_from`, when given). Exit 0 with `ok: <status>`; on timeout exit 1 with `expected …, found: <every row's plain_text, status, trashed_from>`.
- Any other error (missing file, bad arguments): exit 2 with the message.

### `run-e2e.ps1 [-Exe <path>] [-Out <dir>]`

- Defaults: `-Exe dist\noite\noite.exe`, `-Out` a new folder under `$env:TEMP`.
- Header comment: sends real keystrokes; on a PC, run only while the author is away.
- **Setup:**
  1. A fresh data folder `<Out>\data`.
  2. Start noite on it (`--data`), wait until `noite.db` exists (10 s), stop that process, run `prepare`.
  3. Start the harness target; wait for `.ready` (10 s).
  4. Start noite on the folder again; wait until its log has the `started` line (10 s).
- **Steps** (each: activate the target, send the keys, then `expect`):

| # | Keys | Expect |
|---|---|---|
| 1 | `^%j`, `e2e buy milk`, `{ESC}` | text `e2e buy milk`, `active` |
| 2 | `^%b`, then `d` | `done` |
| 3 | `^3`, then `{DEL}` | `trashed`, trashed from `done` |
| 4 | `^4`, then `{DEL}` | `done` |

  Steps 2–4 send to the board, which stays the foreground window between them; the target is activated before step 1 and step 2 only.
- **Teardown** (always, in `finally`): `.stop` for the target (5 s, then kill); stop noite; copy `data\logs\noite.log` to `<Out>`.
- **Result:** one line per step, `step <n> PASS|FAIL <detail>`; then `leaked_chars=<n>` (non-zero fails the run); then `E2E PASS` or `E2E FAIL`. Exit 0 only on pass.

## Part C — CI

- In the `build` job, after **Capture bench**: step **End-to-end** (`shell: powershell`, `timeout-minutes: 5`), PATH and `QT_PLUGIN_PATH` set to the CI Qt as for the benches, `run-e2e.ps1 -Exe build/Release/noite.exe -Out e2e`.
- **Upload e2e results** (`if: always()`): artifact `e2e-results` with `e2e/` (output, `noite.log`, the leak file).
- The workflow stays ASCII-only.

## Errors

| Case | Behaviour |
|---|---|
| The hotkey never reaches noite (step 1 times out) | `step 1 FAIL` with what the database holds (no note), then teardown; CI fails. |
| A keystroke lands in the target | `leaked_chars` > 0 fails the run even if every step passed. |
| noite exits early or never logs `started` | `setup FAIL: …`; teardown; exit 1. |
| Python missing | `setup FAIL: python not found`; exit 1. |

## Testing

- `tst_board_window`: `ctrlDigitSwitchesTab` (each of `Ctrl+1`…`Ctrl+4` sets the model's tab and the tab strip; first card selected), `ctrlDigitIgnoredWhileOverlayOpen`.
- `noite_db.py` has a `--self-test` that builds a temporary database with a `settings` and a `scratches` table and checks `prepare` and `expect` (pass, timeout, trashed-from mismatch); `run-tests.ps1` runs it like the release tools' self-tests.
- The run itself is the end-to-end test; its first CI run is its acceptance.

## Order of work

1. Tab shortcuts (tests first), docs.
2. `noite_db.py` with its self-test, wired into `run-tests.ps1`.
3. `harness-target.ps1` and `run-e2e.ps1`; one local run, only after the author says they are away.
4. CI step and artifact; roadmap and `spec.md` §9 rows.
